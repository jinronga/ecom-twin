# 接入指南

安装与首次启动见 [README](../README.md#快速开始)。本文说明配置位置、可选工具和日常维护，命令均在项目根目录执行。

## 配置和数据位置

| 路径 | 用途 |
| --- | --- |
| `.env` | 飞书和妙手凭证；配置页保存时使用 `0600` 权限 |
| `config/settings.toml` | 本机主配置，参考 [settings.example.toml](../config/settings.example.toml) |
| `config/settings.console.toml` | 控制台保存的覆盖配置，优先于主配置 |
| `data/` | 数据库、日志、任务工作区、截图与运行记录 |
| `memory/` | 人工维护的 Markdown 业务记忆 |
| `skills/` | 项目自带的业务 SOP |

从源码仓库运行时，数据默认放在仓库内。非源码布局下默认数据目录为 `~/Library/Application Support/EcomTwin/`；可用 `ECOM_TWIN_HOME` 覆盖，用 `ECOM_TWIN_RESOURCES` 指定资源目录。应用安装包尚未完成。

控制台覆盖配置优先于主配置，凭证环境变量优先于 `.env` 文件。修改连接或运行时配置后需要重启任务服务。

## 飞书接入与检查

配置页使用 `.venv/bin/ecom-twin setup` 启动，默认地址为 `127.0.0.1:8765`。访问时使用命令输出的完整 token 链接；需要更换端口时，例如：

```bash
.venv/bin/ecom-twin setup --no-browser --port 8767
```

在飞书开放平台启用机器人、设置可用范围和消息接收、读取、发送权限，选择长连接接收事件并订阅 `im.message.receive_v1`，发布应用版本。回复截图需要 `im:resource:upload` 或 `im:resource` 应用身份权限。负责人 `open_id` 必须来自当前应用。

配置页的连接测试检查应用凭证和机器人信息。还需在飞书发送任务，分别确认建单回执、Agent 回复、业务工具调用、图片发送和话题续跑。分身的汇报、提问和截图默认以「话题」形式回复在原消息下，一个任务的往来都在同一话题；会话不支持话题时退回普通引用回复。配置 `[feishu] reply_in_thread = false` 可关闭。从群任务改私聊交付时，第一次建立锚点消息，之后都跟在该消息下。文本和图片私聊都可以建单，图片保存在任务的私有附件目录。

已配置 App ID / Secret 时使用官方 SDK 长连接，无需安装 lark-cli；未配置时仍兼容原 lark-cli 入口。从配置页启动的任务服务随配置服务退出而停止，独立运行使用 `serve` 或下文的后台服务。

## 工具安装与登录

打开页面、保存配置或直接启动 `serve` 时，会检查并自动安装缺失的飞书 SDK、默认与备用 agent CLI。其它运行时可以在页面单独安装；已有可用版本会保留。自动下载使用官方来源：Python `lark-oapi`、npm `@anthropic-ai/claude-code` / `@openai/codex` / `opencode-ai`、Cursor 官方安装脚本。npm 工具在源码运行时安装到仓库下的 `data/tools/`；设置 `ECOM_TWIN_HOME` 后则安装到该目录下的 `data/tools/`。缺少 Node.js 时从官方站点下载 Node.js 22 并核对 SHA-256；Cursor 安装在官方默认用户目录。支持 macOS / Linux 的 arm64 / x64，安装失败可在页面重试；手动配置的错误路径需先修正或清空。

自动安装不包含账号登录。选择运行时后，在终端执行相应命令：

```bash
.venv/bin/ecom-twin login codex
# 或：.venv/bin/ecom-twin login claude_code
# 其他适配器：login cursor / login opencode
.venv/bin/ecom-twin runtimes
```

## 上下文与任务续接

每轮自动读取来源会话近 24 小时、最多 30 条消息，并补充任务原消息、引用和话题回复，分析最新要求及已有进展。记录会去重、脱敏并限制总长度。失败或截断会标明；需要更早的信息时可继续调用飞书上下文工具。

其他会话需加入 `[feishu] readable_chats` 才能按需读取；以个人身份搜索聊天记录默认关闭。群聊还需配置 `[intake] listen_chats`，群内回复和通知由 `send_permissions` 单独控制。

默认运行时为 Codex 时，任务归属判断也使用 Codex。负责人私聊明确说“继续处理”且只有一个近期未完成任务时直接续接；多个候选仍无法确定时，先询问任务号。

## 专用浏览器

网页取证和专用浏览器需要本机安装 Google Chrome。公开页面取证使用 Chrome 的临时无头进程，不需要执行 `browser start`，目标域名需在 `[browser] allowed_domains` 中。需要交互的专用 Chrome 按下文启动；`browser.flow` 则使用独立的 Playwright 环境和平台登录状态。

在配置页开启专用 Chrome，或者合并以下设置到已有的 `[browser]` 配置节：

```toml
[browser]
enabled = true
browser_url = "http://127.0.0.1:9225"
user_data_dir = "~/.agent-chrome-ecom"
interactive = true
auto_login_domains = []
```

```bash
.venv/bin/ecom-twin browser start
```

调试端口应保持空闲，资料目录使用专用目录。启动后运行 `check` 确认连接到专用 Chrome；不要在该浏览器登录卖家中心或广告后台。

启用 `[browser] enabled = true` 后，调度器会在每轮任务（含续跑）开始前准备专用 Chrome：未运行时自动启动，已运行时复用，确认用户目录和调试接口正常后再挂载工具。无需给 Agent 开放终端权限。端口被其他进程占用、用户目录不匹配或启动失败时，会报告具体原因，不会自动切换端口或接管日常浏览器。

内部平台自动登录由负责人按**完整域名**授权，例如 `auto_login_domains = ["wms.example.com"]`。Agent 可以使用明确提供给该平台的凭证登录；该配置不包含子域名或第三方登录页。验证码、短信、MFA 和未授权平台仍交给负责人处理。

域名登录规则通过任务指令传达给 Agent，并非浏览器级网络隔离。登录许可也不等于制单、删除、改价等业务操作许可。

需要走 `browser.flow` 的内部平台流程时，另行配置 `[platforms.<key>]`，安装 Playwright，并保存该平台的登录状态：

```bash
.venv/bin/python -m pip install playwright
.venv/bin/python -m playwright install chromium
.venv/bin/ecom-twin browser-login warehouse
# warehouse 对应自己配置的 [platforms.warehouse]
```

## 截图与桌面操作

网页截图可由 Agent 调用 Chrome MCP 的 `take_screenshot` 写入 `evidence-image prepare` 生成的路径，再由 `evidence-image collect` 检查 PNG、大小和目标路径。需要手动准备截图路径时：

```bash
.venv/bin/ecom-twin evidence-image prepare T-0001
```

桌面窗口取证使用 `evidence-image desktop TASK WINDOW_ID --box x,y,width,height`。图片标注需要 Pillow，README 中的 `evidence` 安装选项已包含它；标注失败时保留原图，需要核对并脱敏后再交付。

桌面操作默认关闭。启用时在主配置中设置 `[computer_use] enabled = true`，或在控制台规则配置中打开。需要安装 ChatGPT 桌面端、在 Codex 中启用 Computer Use，并授予辅助功能和屏幕录制权限；`ecom-twin check` 会显示可用情况。

Codex 使用独立配置目录，禁用内置 Shell 和全局应用连接器，按本轮工具白名单开放能力。浏览器代理检查工具、网址和脚本，截图文件有路径校验；这些检查不能替代对网页业务动作的授权。浏览器动作审计隐藏填写值及脚本正文，但原始 Agent 运行记录可能仍包含任务输入或工具参数，应留在本机。

## 客服回复与话术

1. 在控制台「客服话术」按店铺和语言建立口吻样例、补充禁用说法、字数上限和备注；售后政策细节写入记忆库。
2. 飞书转发买家问题并带上店铺，例如 `tiktok:7300 的买家问：Where is my package?`。
3. Agent 生成回复草稿、中文意思和风险等级；涉及退款、补发、补偿或改订单的事项交给负责人决定。
4. 人工复制草稿到平台发送，在「客服草稿」记录原样发送、修改后发送或不发。

话术依次匹配「店铺/语言 → 店铺 → */语言 → default → 内置默认」。预览只做检查、不发送消息。当前仅实现起草和人工发送结果登记，未接入平台客服收发接口。风险等级来自关键词规则，仍需人工核对具体语境。

群聊代发会检查禁用措辞、篇幅和铺垫；可在「规则配置」的 `[outbound]` 中调整。任务指令同时强调先确认后续工作的归属，不替负责人承诺接手他人的任务。

## 控制台与业务记忆

```bash
.venv/bin/ecom-twin console
```

负责人链接可维护配置、话术和记忆；运营链接可查看页面、采纳或驳回记忆草稿、预览客服话术和登记草稿发送结果，不能修改规则配置、话术配置或直接编辑、导入、回滚记忆。控制台默认端口为 `8766`，可查看任务、Listing 差异、召回记录、成本和影子模式评估，并切换日夜模式。

任务看板支持跨列拖拽和同列排序，正在运行的任务不能跨列拖动。任务详情底部可以继续输入，把补充要求交给同一任务。控制台右下角的「问分身」会直接处理控制台对话，不会把回复发到飞书。

每轮任务先加载记忆索引，Agent 根据动作使用 `read_memory` 读取全文，必要时通过 `search_memory` 搜索，读取情况写入召回日志。Agent 提出的记忆变更先保存为草稿，由人审阅后采纳。

```bash
.venv/bin/ecom-twin memory export --out 记忆包.txt  # 导出记忆包（纯文本，可直接发给同事看）
.venv/bin/ecom-twin memory import 记忆包.txt        # 导入；同名覆盖前自动留历史版本
.venv/bin/ecom-twin memory history 标识             # 历史版本
.venv/bin/ecom-twin memory rollback 标识 版本文件    # 回滚
.venv/bin/ecom-twin memory suggest 标识             # 让本机 Claude Code 按写法标准给描述提建议（不落盘）
```

## 选品、雷达与问分身

选品规则保存在 `memory/selection-*.md`，按市场配置价格带、重量、毛利、佣金、运费、退货率、打分权重和排除类目。控制台可以试算单个候选；Agent 必须先取得有效调研快照，再调用代码打分。剧本中修改「规则」后仍需人工采纳，只有 `auto_adopt_sections` 指定的章节可以自动采纳，且草稿不能夹带其他章节。

选品雷达规则保存在 `memory/` 中的 `type: radar` 记忆，支持 cron、时区、有效期和启用开关。没有信号时只记录运行结果，不创建任务；发现新词、连续新词、节日备货窗口或痛点词时创建雷达任务并生成线索。线索可以标记为「在看」「放弃」或「转选品」，转选品是原子操作，不会因重复点击创建多个任务。

第三方选品数据接口是可选项，在 `settings.toml` 配置：

```toml
[research]
third_party_url = ""
third_party_key_env = ""
```

密钥填写在 `.env`，配置里只写环境变量名。第三方返回的数据如果标记为示例数据，不会作为选品依据。

## 审批回复

发布等受支持的提案执行动作需要审批，支持代理审批和高风险双人审批；执行器会核对店铺范围、限额和有效期。`browser.flow` 通过提案进入审批流程，专用 Chrome 的交互操作仍依赖 Agent 在提交前取得授权。

在审批卡片下回复：

```text
批准 P-0001
拒绝 P-0001 1 成本数据不对
```

将 `P-0001` 替换为审批卡片中的提案号。拒绝格式为 `拒绝 提案号 原因编号 备注`；原因必填，编号为 `1` 数据不对、`2` 判断不对、`3` 时机不对、`4` 违反偏好、`5` 其他，也可直接填写对应的原因文字。示例中的 `1` 表示“数据不对”，备注可省略。

## 常用命令

| 命令 | 用途 |
| --- | --- |
| `ecom-twin setup` | 配置飞书与运行时 |
| `ecom-twin check` | 基础连接和配置检查 |
| `ecom-twin runtimes` | 检查各 Agent CLI |
| `ecom-twin serve` | 前台任务服务 |
| `ecom-twin serve --local` | 不连接飞书，只运行控制台任务、问分身、定时作业和选品雷达 |
| `ecom-twin console` | 本地管理控制台 |
| `ecom-twin health` | 妙手只读连接检查 |
| `ecom-twin memory drafts` | 查看记忆草稿 |
| `ecom-twin memory recalls` | 查看召回记录 |
| `ecom-twin costs` | 查看成本统计 |
| `ecom-twin shadow report` | 查看影子模式评估 |

未激活虚拟环境时，为命令加上 `.venv/bin/`。更多选项可通过 `.venv/bin/ecom-twin --help` 查看。

本地发起任务、将飞书输出改为终端打印：

```bash
.venv/bin/ecom-twin ask "列出我的 TikTok 店铺" --console
```

`--console` 只改变消息投递方式，仍会调用真实 Agent 和业务工具，不是业务操作的 dry-run。

## 后台运行（macOS）

确认前台任务正常后，先停止前台 `serve`，再安装并启动 launchd 服务：

```bash
.venv/bin/ecom-twin start       # 登录后自启，异常退出后自动拉起
.venv/bin/ecom-twin status
.venv/bin/ecom-twin logs -n 100
.venv/bin/ecom-twin restart
.venv/bin/ecom-twin stop        # 停止本次运行，下次登录仍可能自启
.venv/bin/ecom-twin uninstall   # 移除常驻配置，保留个人数据
```

后台服务只运行任务监听与调度；控制台仍需单独启动。从 `setup` 页面启动的任务服务随配置服务退出而停止，独立运行应使用 `serve` 或 launchd。
